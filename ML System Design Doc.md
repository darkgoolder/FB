▎ML System Design Doc: Распознавание стороны вагона (Лицевая-хвостовая часть)  


▎1.1. Зачем идем в разработку продукта?  

**Бизнес-цель Product Owner:**  

Разработка системы распознавания стороны вагонов позволит улучшить процессы идентификации и учета вагонов на железнодорожном транспорте, повысив эффективность логистики и минимизировав ошибки при обработке данных.  

**Почему станет лучше, чем сейчас, от использования ML:**  

Использование ML позволит автоматизировать процесс распознавания сторон вагонов, что значительно ускорит обработку информации и уменьшит количество ошибок, связанных с человеческим фактором. В настоящее время многие процессы выполняются вручную, что требует много времени и ресурсов.  

**Что будем считать успехом итерации с точки зрения бизнеса:**  

Успехом будет считаться точность распознавания не менее 90% на тестовых данных, а также сокращение времени обработки вагонов на 35% по сравнению с текущими методами.  


▎1.2. Бизнес-требования и ограничения  

**Краткое описание БТ и ссылки на детальные документы с бизнес-требованиями:**    

Основные бизнес-требования включают:    
• Автоматическое распознавание лицевой и хвостовой части вагонов;  
• Интеграция с существующими системами учета;  
• Обеспечение высокой скорости обработки данных  

**Бизнес-ограничения:**  

• Ограниченный бюджет на разработку и внедрение;  
• Необходимость соблюдения технических норм для интеграции в существующие процессы;  

**Что мы ожидаем от конкретной итерации:** 

В данной итерации мы ожидаем создать прототип модели, которая сможет обрабатывать данные в реальном времени и обеспечивать высокую точность распознавания.  

**Описание бизнес-процесса пилота:**   

Модель будет интегрирована в систему учета вагонов, где будет использоваться для автоматического определения стороны вагона при его поступлении на станцию. Данные будут передаваться в систему учета для дальнейшей обработки.  

**Что считаем успешным пилотом? Критерии успеха и возможные пути развития проекта:**  

Успешным пилотом будет считаться достижение точности распознавания не ниже 90% на реальных данных. Возможные пути развития включают расширение функционала для распознавания других характеристик вагонов и интеграцию с другими системами.  


▎1.3. Что входит в скоуп проекта/итерации, что не входит  

**На закрытие каких БТ подписываемся в данной итерации:**  

• Разработка модели для распознавания лицевой и хвостовой части вагонов;  
• Определение идентификационного номера вагона при нахождении на изображении  
• Интеграция модели с существующей системой учета вагонов;  
• Разработка интерфейса пользователя для взаимодействия с моделью.  

**Что не будет закрыто:**  

• Работа в разных сложных климатических условиях  

**Описание результата с точки зрения качества кода и воспроизводимости решения:**  

Код будет написан с учетом лучших практик разработки, включая документацию, тестирование и использование систем контроля версий. Модель будет воспроизводима на других наборах данных при соблюдении аналогичных условий.  

**Описание планируемого технического долга:**  

Оставим для дальнейшей продуктивизации улучшение модели с использованием дополнительных данных, а также разработку более удобного интерфейса пользователя для  взаимодействия с системой, затронув работу с погодными условиями.  

▎1.4. Предпосылки решения  

**Описание всех общих предпосылок решения:**  

• Используемые блоки данных: изображения вагонов, метаданные о каждом вагоне (например, тип, номер);  
• Горизонт прогноза: модель будет обучена на исторических данных за последний год;  
• Гранулярность модели: модель будет работать на уровне отдельных изображений вагонов, обеспечивая высокую точность распознавания.  

**Обоснование от запроса бизнеса:**  

Запрос бизнеса основан на необходимости повышения эффективности процессов учета вагонов и минимизации ошибок, связанных с ручным вводом данных. Использование ML позволяет достичь этих целей за счет автоматизации и повышения точности обработки информации.  



▎2. Методология Data Scientist


▎2.1. Постановка задачи  

**Что делаем с технической точки зрения:**    
Разработка классификационной модели машинного обучения для распознавания стороны вагона (лицевая и хвостовая часть). Основная задача заключается в создании системы, которая будет автоматически определять сторону вагона на основе предоставленных изображений, что позволит улучшить процессы идентификации и управления подвижным составом.

▎Описание ключевых этапов  

1. Сбор данных:  
   Сбор изображений вагонов с различными углами и условиями освещения для обеспечения разнообразия.  

2. Предобработка данных:  
   Очистка данных от шумов, аугментация изображений для увеличения объема выборки (например, повороты, изменения яркости и контрастности).  

3. Разделение выборок:  
   Деление данных на обучающую, валидационную и тестовую выборки для оценки качества модели.  

4. Построение моделей:  
   – Бейслайн: Использование логистической регрессии для создания базовой модели.  
   – MVP: Применение сверточных нейронных сетей (CNN) для повышения точности распознавания.  

5. Оптимизация модели:  
   Настройка гиперпараметров и отбор наиболее значимых признаков для улучшения производительности модели.  

6. Тестирование модели:  
   Оценка качества модели с использованием метрик, таких как точность (accuracy), полнота (recall) и F1-score.  

7. Закрытие технического долга:  
   Исправление выявленных проблем и недостатков в модели или процессе разработки.  

8. Подготовка пилота:  
   Разработка API для интеграции модели в существующие системы и подготовка документации для пользователей.  

Эта блок-схема и описание этапов позволяют четко видеть процесс разработки системы распознавания стороны вагона и его ключевые компоненты, что поможет в дальнейшем планировании и реализации проекта  


▎2.3. Этапы решения задачи Data Scientist  

▎Этап 1 - Подготовка данных  

| Название данных                     | Есть ли данные в компании |Требуемый ресурс для получения данных      | Проверено ли качество данных|
|-------------------------------------|---------------------------|-------------------------------------------|-----------------------------|
| Изображения вагонов                 | Да                        | Data Engineer, Data Scientist             | Да                          |
| Метаданные (тип вагона, угол съемки)| Да                        | Data Engineer                             | Да                          |
| Аннотации (лицевая/хвостовая часть) | Да                        | Data Scientist, аннотаторы                | Да                          |

**Краткое описание результата этапа:**  
На выходе необходимо получить витрину данных с изображениями вагонов, их метаданными и аннотациями, готовую для дальнейшего анализа и обучения моделей.  

---  

▎Этап 2 - Подготовка прогнозных моделей  

**Бейслайн:**  
• Техника: Использование логистической регрессии для классификации изображений как "лицевая" или "хвостовая" часть;  
• Формирование выборки: Разделение на обучающую (75%), валидационную (15%) и тестовую (10%) выборки. Использование случайной выборки изображений с равным количеством лицевых и хвостовых частей;  
• Целевая переменная: Класс (лицевая/хвостовая часть);  
• Метрики качества: Accuracy ≥ 75% по тестовой выборке;
• Риски: Модель может не справляться с изображениями, сделанными в плохих погодных условиях или с изображениями низкого качества (Ниже 480p)  

**MVP:**  
• Техника: Применение сверточной нейронной сети (CNN) для более точного распознавания;  
• Формирование выборки: Аналогично бейзлайну, но с увеличением объема данных за счет аугментации (повороты, изменения яркости, резкости, затемнение и осветления);  
• Целевая переменная: Класс (лицевая/хвостовая часть);  
• Метрики качества: Accuracy ≥ 75% по тестовой выборке, F1-score ≥ 0.7;  
• Риски: Сложности с переобучением модели из-за недостатка разнообразия в данных;  

**Необходимый результат этапа:**  
Создание базовой модели (бейзлайн) и улучшенной модели (MVP), которые смогут классифицировать изображения с заданной точностью.  

---  

▎Этап 3 - Интерпретация моделей  

**Бейслайн:**  
• Техника: Анализ коэффициентов логистической регрессии для понимания влияния различных признаков на предсказание;  
• Бизнес-проверка: Обсуждение результатов для оценки значимости признаков.



**MVP:**  
• Техника: Использование методов интерпретации CNN, таких как Grad-CAM для визуализации областей изображения, которые влияют на предсказание;  
• Бизнес-проверка: Презентация результатов интерпретации ключевым заинтересованным сторонам.  

**Необходимый результат этапа:**  
Понимание того, какие признаки наиболее важны для классификации, и согласование с бизнесом.  

---  

▎Этап 4 - Интеграция бизнес правил для расчета бизнес-метрик качества модели  

**Бейслайн и MVP:**  
• Техника: Определение бизнес-метрик, таких как количество правильно классифицированных вагонов и скорость обработки изображений;  
• Бизнес-проверка: Согласование метрик  

**Необходимый результат этапа:**  
Четкие бизнес-метрики, которые будут использоваться для оценки успешности внедрения модели.  

---  

▎Этап 5 - Подготовка инференса модели по итерациям  

**Бейслайн и MVP:**  
• Техника: Разработка API для инференса, который будет принимать изображение и возвращать предсказание;  
• Бизнес-проверка: Тестирование API с реальными данными.  

**Необходимый результат этапа:**    
Рабочий API для инференса модели.  

---  

▎Этап 6 - Интеграция бизнес правил  

**ейслайн и MVP:**  
• Техника: Внедрение бизнес-правил, таких как автоматическое уведомление о неверной классификации;  
• Бизнес-проверка: Обсуждение правил  

**Необходимый результат этапа:**  
Интегрированные бизнес-правила в процесс работы модели.  

---  

▎Этап 7 - Разработка оптимизатора (выбор оптимальной итерации)  

**Бейслайн и MVP:**  
• Техника: Анализ производительности различных версий модели и выбор лучшей на основе метрик;  
• Бизнес-проверка: Представление результатов анализа заинтересованным сторонам.  

**Необходимый результат этапа:**  
Оптимизированная модель, обеспечивающая наилучшие результаты.  

---  

▎Этап 8 - Подготовка финального отчета для бизнеса  

**Бейслайн и MVP:**  
• Техника: Составление отчета с описанием процесса, результатов и рекомендаций;  
• Бизнес-проверка: Презентация отчета ключевым заинтересованным сторонам.  

**Необходимый результат этапа:**   
Финальный отчет, который может быть использован для принятия решений о дальнейшем развитии продукта.
